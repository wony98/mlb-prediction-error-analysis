# 규칙 탐지 누수 피처 vs 제거 세트 재실험 (MLflow 추적, 2026-10-23)

이 문서는 `experiments/mlflow/train_clean_vs_leaky.py`를 2026-10-23에 로컬 CPU에서 실행한 결과와 그에 따른 판단을 적는다. 과거 운영 당시의 기록을 옮긴 것이 아니라 새로 돌린 실행이다. 각 run의 파라미터, 지표, 산출물과 실행 코드 사본을 MLflow(sqlite 백엔드)에 남겼다. 실행 환경과 설계는 [experiments/mlflow/README.md](../experiments/mlflow/README.md)에 있다. 유효 결과는 batch `20261023T064114`(커밋 `e73544e`)다.

## 1. 무엇을 비교했나

연구 보고서 4절에서 설명한 누수(현재 경기 결과가 포함된 선발투수·타선 누적 지표)를 포함한 피처 세트와, 그 컬럼을 뺀 세트를 학습해 비교했다. 데이터와 분할, 하이퍼파라미터는 같게 맞췄다.

- 데이터: 2021~2025 시즌 12,122경기, 250열 (SHA-256은 각 run의 `data_sha256` 태그). 원본 열 이름은 로컬 매핑으로 저장소의 중립 이름에 연결했다(29열).
- 분할: train ≤2023 (`home_win` 7,279경기 / `upper` 6,967) / val 2024 (2,422 / 2,319) / test 2025 (2,421 / 2,312). `upper`는 기준점 결측 524경기 제외
- 모델: LightGBM, `src/_mlb_train_v3.LGB_PARAMS` 고정, val AUC early stopping
- "누수" 판정의 범위: `src/_mlb_train_v3.is_leaky`의 이름 규칙이 탐지하는 현재 경기 포함 누적 스탯 열(era/whip/k9/bb9/hr9/ops/wr/rs/ra 계열). lag1·roll·prior 계열은 경기 전 시점 값이라 유지. 규칙 탐지 0열은 전체 입력 시점 누수가 없다는 검증이 아니다. 시장 피처(시장가격·기준점) 등 다른 열의 예측 시점은 이 실험에서 감사하지 않았다.
- as-of-prior 선발투수 지표: (game_pk, side) 중복 키 18개·9경기는 어느 값이 맞는지 원본 근거가 없어 해당 경기의 값을 제외(NaN)했다. 경기 행은 삭제하지 않았다. 제외 목록은 `outputs/data_checks.json`.

## 3. 해석 (확인된 사실과 판단을 구분)

확인(이번 분할·고정 설정 안에서):
- 규칙 탐지 열을 모두 가진 세트(full_leaky·base_v2_leaky, upper의 clean_swap 포함)는 test AUC 0.64~0.67이다. 승패 베이스라인에서 선발투수 3지표만 교체한 부분 교체 세트(home_win base_v2_clean_swap, 탐지 4열 잔존)는 0.581(시장가격 있는 경기)로 제거 세트와 같은 수준이다. 규칙 탐지 열을 모두 뺀 세트는 0.49~0.58이다.
- 홈 승리에서 규칙 탐지 열이 없는 세트(0.579~0.580)와 시장가격 환산 확률(0.584)은 같은 2,416경기에서 0.005 안쪽 차이다. 이 차이가 통계적으로 의미 있는지는 검정하지 않았다.
- 총득점에서 규칙 탐지 열이 없는 세트는 0.485~0.489(시장가격 있는 경기 기준)로 우연 수준이다.
- `upper`의 `base_v2_clean_swap`은 `base_v2_leaky`와 결과가 같다. `experiments/leakage`의 교체 규칙(`CLEAN_SWAP`)이 승패 베이스라인의 era/k9/bb9_diff만 바꾸므로, 총득점 베이스라인(`_sum`·`_max` 계열)에는 적용되지 않아 규칙 탐지 열 14개가 그대로 남는다. 이 세트는 `upper`에서는 제거 비교가 아니다.
- `home_win`의 `base_v2_clean_swap`에도 ops_diff·wr5_diff·wr10_diff·rs10_diff 4열이 남는다. 교체 범위가 선발투수 3지표에 한정됐기 때문이다.
- as-of-prior 지표를 더한 `full_clean_plus_spa`는 `full_clean`과 차이가 거의 없다(0.579 vs 0.580).

판단(추정, 이 실험 범위 안에서):
- 과거 노트북·화면 출력에 남아 있던 0.65 이상의 AUC는 규칙이 탐지하는 누적 스탯 열이 만든 숫자로 보는 것이 맞다. 보고서가 누수를 "입력 시점 오류"로 다룬 것과 일치한다.
- 이 분할과 이 설정에서는 규칙 탐지 열을 뺀 모델이 시장가격 환산 확률을 넘지 못했다. 공개 README의 "시장 확률보다 나은 예측력은 확인하지 못함"과 같은 결과다. 다른 분할·다른 피처 공학·다른 모델에서도 그렇다는 뜻은 아니며, 시장 대비 우위 유무를 일반화하지 않는다.
- 총득점은 이 설정에서 규칙 탐지 열을 빼면 신호가 없다. 누적 득점·실점 지표에 결과가 섞여 들어간 것이 0.64의 원인으로 보인다.

## 4. 결정

1. 성과를 말할 때 쓰는 숫자는 규칙 탐지 열이 없는 세트(`full_clean`, `full_clean_plus_spa`)의 값만 쓴다. 누수 세트의 값은 "누수가 만든 허수"의 예시로만 인용한다.
2. 기준 모델 구성은 `full_clean_plus_spa`(as-of-prior 포함, `_mlb_train_deploy.py`와 같은 구성)로 둔다. 성능 차이는 없지만 입력 시점이 명확한 쪽을 택한다.
3. `experiments/leakage`의 교체 규칙은 승패 베이스라인 전용임을 README에 명시한다. 총득점 쪽 제거 비교는 이 문서의 `full_clean` 결과를 쓴다.
4. 이력서·포트폴리오 문장은 검증 범위에 맞춘다. 예: "기존 누수 판정 규칙으로 선별한 피처 세트를 같은 분할에서 비교하고 실행 설정·결과를 MLflow로 추적했다. 규칙 탐지 열을 뺀 모델은 이 분할에서 시장가격 환산 확률과 같은 수준(test AUC 0.58)이었다." 떨어진 숫자를 그대로 적고 부풀리지 않는다.

## 5. 한계

- 하이퍼파라미터를 세트별로 다시 맞추지 않았다. 제거 세트에 맞춘 탐색을 하면 숫자가 달라질 수 있다.
- 분할이 한 가지(2024 val / 2025 test)다. `experiments/leakage`의 시즌별 walk-forward와는 프로토콜이 다르다.
- 누수 판정은 이름 규칙이다. 시장 피처·기타 열의 예측 시점을 포함한 전체 시간적 누수 감사는 하지 않았다.
- 시장가격 환산 확률과의 비교는 같은 경기 집합 기준이지만 유의성 검정은 하지 않았다.
- as-of-prior 지표의 커버리지는 97.9%이며, 중복 키 9경기는 제외했다. 결측은 LightGBM이 결측으로 처리했다.
- 2026년 이후 자료와 당시 운영 모델의 실제 적중은 이 실험 범위 밖이다. 이 결과로 과거 운영 성과를 재평가하지 않는다.

## 6. 재현

`experiments/mlflow/README.md`의 실행 명령을 따른다. 각 run에는 데이터·spa·매핑 파일 SHA-256, 실행 스크립트·피처 정의·requirements의 SHA-256과 사본(`code_snapshot/`), git 커밋이 태그·아티팩트로 있다. 같은 파일·같은 버전·`random_state=42`로 돌리면 가까운 숫자가 나와야 하지만, 스레드 수(`--n-jobs`)에 따른 차이의 크기는 측정하지 않았고 재현을 두 번 실행해 확인한 것도 아니다.
