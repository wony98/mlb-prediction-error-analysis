# MLB 개발·연구 작업 이력

[연구 요약](../README.md) · [상세 보고서](RESEARCH_REPORT.md)

아래는 개발 과정에서 다룬 문제와 구현·실험 결과를 주제별로 정리한 기록이다. 같은 자료의 여러 사본과 반복 실행을 별개의 연구 성과로 세지 않았다. 실제 구현, 비교 실험, 채택하지 않은 계획을 함께 남겼다.

## 초기 접근과 모델 개발

| 작업 | 목적과 내용 |
|---|---|
| GPT 분석 지침과 결과 기록 | 2025년 사전 시도에서 분야별 가중치, 홈·원정 비교, 입력 시각·단위 통일과 결과 피드백을 정리했다. 지침의 목표 적중률을 검증된 성과로 사용하지 않았다. |
| 시범경기에서 일별 수집으로 | 2026년에는 경기 전 수집→GPT 입력→경기 후 기록의 절차를 만들고 시범·정규시즌 전환을 관리했다. |
| 평가 원칙 수립 | 소수 경기 결과로 규칙을 즉시 바꾸자는 제안에 대한 반론을 검토했다. Claude가 제안한 사전 태깅, 결과 후 태그 수정 금지, 평가 기준 고정을 내가 채택했다. |
| 규칙 계산 엔진 | 선발, 불펜, 타선, 구장과 상대전적의 가중합을 시험했다. 지표별 유리·불리 집단을 비교해 채택·탈락을 정하고, 이후 가중치 탐색에서 그 선택을 다시 비교했다. |
| 과거 3시즌 입력 생성 | 연도별 생성기와 실행 래퍼로 선발·타자·불펜·환경·기준점 자료를 재구성했다. 시즌 고정과 시범경기 기록 우선 선택 문제를 조사했다. |
| 초기 홈승 학습 실험 | 3개년 자료, 세 모델과 확률 보정을 시험했다. 같은 경기 OPS와 시즌 전체 구장 평균을 입력에 넣은 시점 문제를 코드에서 확인했다. 당시 이를 인지했는지는 미확인이다. |
| 학습 모델과 버전 비교 | Logistic Regression, XGBoost, LightGBM을 비교하고 결측·상관·다중공선성, 정확도·AUC·Brier score를 조사했다. 규칙 엔진의 버전과 학습 모델의 버전을 구분했다. |
| 모델 선택과 축소 | LR·LGB 설정과 혼합비를 탐색하고, 운영용 모델의 입력을 승패 12개·총득점 22개까지 줄인 버전을 만들었다. 같은 버전명의 보고서라도 평가 분모가 다르면 별도로 다뤘다. |
| 추가 지표 실험 계획 | Statcast 특성을 더하는 별도 시험을 설계했다. 계획 문서가 있다는 사실과 실행·효과 검증을 구분했다. |
| 도메인 확장 | 선수 좌우 조건, 상대 팀 기록, 부상·거래, Statcast, 타순 구성과 시장 이동을 비교했다. 전체 자료에 적합한 모델 위에서 계산한 성적은 독립 평가로 보지 않았다. |
| 시점 보정과 후기 모델 | 운영 모델의 누적 성적에 당일 결과가 포함된 문제를 조사했다. 입력을 재구성하고 승패는 단일 LightGBM 분류, 총득점은 회귀로 바꿨다. |
| 일별 기록과 시장 자료 | Colab에서 로컬 Python 실행으로 확장했다. 시장 자료는 모델 입력·확률 비교·총득점 기준선으로 사용하고, 경기 후 결측 시장가격이 경기 전 값을 덮지 않도록 했다. |

## 데이터 수집과 정합성

| 작업 | 목적·구현·결과 |
|---|---|
| 과거 입력 복원 | 구형 스키마와 라인업 결측을 추적하고 재생용 입력을 복원했다. 실제 경기에서 복원한 명단과 경기 전에 발표된 명단은 구분했다. |
| 원본 경기 내용과 선수 카드 연결 | 원본 PBP를 갱신하고 날짜별 사건 기록을 누적했다. 분야별 추론, 선수 카드와 원본 상세 필드를 연결해 점수 요약보다 구체적인 경기 내용을 다루도록 했다. |
| 투수·타자 직접 맞대결 | 선수 ID 쌍과 기간·관측 수를 확정 타순에 연결했다. 맞대결 표본이 없는 경우와 선수 식별 자체가 없는 경우를 나눴다. |
| 구장 방향과 바람 | 구장의 방향에 바람이 불어오는 방향과 불어가는 방향을 결합하는 연구를 진행했다. 운영 분석에는 적용하지 않은 실험으로 남겼다. |

## 선수별 근거와 네레이터

| 작업 | 목적·구현·결과 |
|---|---|
| 검색 라벨의 오분류 수정 | 원문을 보존한 채 검색용 라벨을 만들고, 선수 이름의 일부나 부정어가 일반 위험 단어에 잘못 매칭되는 사례를 수정했다. 라벨을 자동 방향 결정 규칙으로 사용하지 않았다. |
| 모델과 네레이터의 판단 차이 | 맞음·틀림·보류의 조합을 구분하고, 예측 순간의 입력과 모델 기여도를 별도 저장했다. 과거 CSV로 재구성한 설명은 당시 저장한 근거와 구분해 다음 회고에 연결했다. |
| 당일 선수와 상대 방향 정렬 | 지지·위험·혼재를 어느 팀에 대한 근거인지 표시하고, 당일 선발·타순으로 범위를 맞췄다. 넓은 투수 후보 목록의 다른 선발이 당일 근거에 들어가는 문제를 수정했다. |
| 정보 전달·열람·반영 분리 | 반대 근거 필수화, 카드별 응답, 분할 추론, 프롬프트 도달 검사를 시험했다. 형식을 통과해도 근거가 해석·최종 판단에 반영되지 않을 수 있음을 확인했다. |
| 중복 근거와 투표 방식 비교 | 같은 근거가 여러 형식으로 반복될 때 중복 집계하지 않도록 분야별로 정리했다. 수치 모델의 결과를 한 표로 집계하는 방식과 근거 방향을 읽는 방식을 구분하고 판단 일관성을 비교했다. |
| 상대 방향과 총득점 교훈 전달 | 최종 선택의 상대 방향 근거를 대조하고, 총득점 교훈이 입력에 빠지는 경로를 수정했다. 넓은 팀명 매칭으로 다른 팀 선수의 교훈이 들어가는 문제도 좁혔다. |

## 오류 분석과 회고

| 작업 | 목적·구현·결과 |
|---|---|
| 성적이 나빴던 날의 원인 조사 | 날짜 선정 기준과 평가 분모를 먼저 확인하고 경고 조건을 비교했다. 광범위한 경고로 선택을 막는 방식의 개선 효과는 입증하지 못했다. |
| 선수별 사전 근거은행 | 틀린 사례에 맞은 사례와 다른 날짜를 추가하고 양 팀 방향을 구분했다. 자연어 경기 맥락을 보존하는 목적에 맞춰 연구를 재정의했으며, 일부 실시간 검색 계획은 채택하지 않았다. |
| 새로 종료된 경기의 증분 처리 | 진행 중 경기와 결과 없는 경기를 분리하고, 새로 끝난 경기만 회고와 누적 기록에 반영하도록 했다. 기대한 경기 집합과 실제 완료 집합을 대조했다. |
| 누적 회고를 다음 분석에 연결 | 과거 누적 기록과 당일 환경·라인업·불펜 요약을 연결했다. 최근 기록부터 찾는 방식과 전날 자료만 사용하는 범위를 구별했다. |
| 사전 위험과 판단 누락 후보 기록 | 선수별 위험과 시장 확률을 비교하고, 사전 자료에 있었으나 반영하지 못했을 가능성을 연구용 기록으로 남겼다. 단어 기반 분류를 확정적인 경기 원인으로 보지는 않았다. |
| 위험과 지지 근거의 균형 | 위험뿐 아니라 맞은 이유도 같은 형식으로 읽고, 지지·위험의 강도와 조합을 시험했다. 결과를 보고 고른 원인에서 나온 높은 포착률은 실제 사전 예측 정확도와 분리했다. |
| 시즌 단위 비교 | 2026년과 2025년 시즌을 대상으로 결과 원인에 연결되는 사전정보를 비교했다. 이미 결과를 아는 상태에서의 원인 포착과 보지 않은 경기의 예측을 구분했다. |
| 승패와 총득점 회고 분리 | 총득점 증가·억제에 초점을 맞춘 별도 회고와 종합 구조를 만들었다. 전체 타석과 선택한 원본 상세를 연결하고 초기 자료를 보정했으며, 과도한 상회 방향과 시점 제한 평가의 차이도 기록했다. |
| 사후 편향의 구분 | 사전에 관련 맥락이 있었다는 사실과 실제로 판단에서 놓쳤다는 주장을 구분했다. 검증되지 않은 설명은 관찰 자료로 남기고 다음 분석의 근거와 구분했다. |

## 판단기준과 검증

| 작업 | 목적·구현·결과 |
|---|---|
| 경고 조건 도입 전 비교 | 순차 평가와 제한된 과거 재생으로 경고의 효과를 확인하고 실험 범위를 격리했다. 부분적인 PBP 자료 때문에 사전 근거가 지워지는 연결 오류도 수정했다. |
| 위험 응답과 실패 부분 재처리 | 분석에 적은 위험을 최종 판단에서 어떻게 다뤘는지 답하도록 했다. 실패 블록만 재추론하고, 빈 판단을 채우는 것과 기존 방향을 바꾸는 것의 승인·검증을 분리했다. |
| 후보 방향과 보류 표시 | 보류하더라도 후보 방향을 별도로 남기고, 검토 조건이 오답만 걸러내는지 맞은 선택도 제거하는지 비교했다. 일괄 보류의 손해를 함께 기록했다. |
| 강도 표시와 경로 개수 검증 | 위험 등급이나 지지 경로 개수만으로 방향을 판단할 수 있는지 과거 자료로 비교했다. 결과 연결과 값 파싱을 점검했으며 광범위한 자동 규칙은 적용하지 않았다. |
| 보류의 기회비용과 평가 분모 | 모델은 맞고 네레이터는 보류한 경우를 비교했다. 모든 자료의 교집합만 평가해 표본을 과도하게 줄이지 않도록 필수 입력과 추가 자료의 범위를 나눴다. |
| 경기 맥락을 판단기준으로 표현 | 단순 유형·점수표에서 맞은/틀린 사례집, 승패/총득점 분리, 방향 기준 추출로 설계를 바꿨다. 결과를 가린 입력 묶음과 LLM 재생을 시험하며 정답을 본 수동 결과와 구분했다. |
| 검색 후 필수조건·무효조건 대조 | 선수 역할별 승리·득점 경로를 보존하고, 검색된 기준의 조건을 참·거짓·불명으로 판정했다. 검색 점수 자체가 최종 선택 권한이 되지 않도록 적용 기록을 만들었다. |
| 앞으로의 경기로 검증하는 실행 계획 | 경기와 비교 조건을 미리 고정해 검증하는 제어 코드를 구현했다. 코드 준비와 실제 검증 실행 완료는 별도로 기록했다. |
| 기준의 재사용성과 추출 품질 | 과거 날짜 비교, 선수 역할 익명화, 결과를 가린 재도출과 두 AI의 도구 조건을 맞춘 비교를 수행했다. 자기 경기 기준 재사용과 후대 기준 사용의 한계를 남겼고 품질 동등성을 입증하지 못한 분업 확대는 보류했다. |
| 양 팀 반론과 최종 판정 | 항목별 근거 확인, 양 팀 경로, 여러 관점의 주장과 최종 심사, 신뢰도 비교를 시험했다. 검사 통과 후에도 공통 오판과 과도한 보류가 남는 사례를 기록했다. |
| 검증 전 가설의 적용 제한 | 경기 결과에서 추출한 조건은 검증 전 가설로 보관하고 자기 경기로 성능을 입증하지 않도록 했다. 배치 크기별 실행 준비와 측정을 실제 추론 완료와 구분했다. |
| 판정 충분성과 메커니즘 강도 | 허용 파일만 읽는 고정 5경기·24회 추론에서 잘못된 자기경기·미래 참조는 0건이었다. 판정 충분성의 일치도 70%, kappa 0.524는 기준 미달이었고, 메커니즘 강도는 80%, 0.762로 통과했다. 결합 기준 미달로 96경기 비교를 진행하지 않았다. |
| 근거 처리 완전성과 과도한 보류 | 20경기 1,419항목의 처리 누락·중복은 0이었지만 승패 20/20, 총득점 19/20이 보류됐다. 정보 처리 조건을 만족하는 것과 유용한 방향 판단을 구분했다. |
| 방향 추론과 유지·보류 후처리 | 후처리가 후보 방향을 바꾸지 못하도록 하고 고정 평가 자료에서 방법을 비교했다. 코드·계약 검토는 완료했지만 통계 승격 기준을 통과하지 못해 운영에 적용하지 않고 연구를 종료했다. 원격 갱신과 선수 누적자료 연결도 이 과정에서 보완했다. |

## 재현성과 입력 보호

| 작업 | 목적·구현·결과 |
|---|---|
| 재분석 격리와 중복 실행 방지 | 별도 출력 폴더만으로 입력 변경을 막을 수 없음을 확인하고 읽기 전용 진입점과 대상 경기 범위를 분리했다. 새 추론·재사용 구분, 파서 수정, 중복 실행 잠금과 종료 정리도 연결했다. |
| 실험 출력 정책과 파서 | 격리 실험이 실제 운영 출력으로 이어지지 않도록 차단 순서를 점검하고, 한글 출력 표식 파싱을 수정했다. 노출된 선택 수 증가와 판단 개선을 구별했다. |
| 실제 사용한 분석 기록 추적 | 어느 경기 범위에서 어떤 추론을 사용했는지 찾아 대조했다. 한글 조사와 영문 이름 매칭으로 문자열 검사 오분류를 줄였으며, 문자 일치를 깊은 의미 이해와 구별했다. |
| 시점이 제한된 과거 재생 | 목표일보다 이전 자료만 재구성하고 원본·입력 해시를 보존했다. 실제 등판한 구원투수 목록 같은 사후 정보가 경기 전 판단에 들어가지 않게 구분했다. |

## 협업과 실행 기반

| 작업 | 목적·구현·결과 |
|---|---|
| 설계·검토 기록 연결 | 설계 제안, 반박, 검증 결과와 산출물을 연결하고 작업 상태와 변경 이력을 관리했다. 두 AI가 서로 다른 상태를 전제로 작업하지 않도록 인수인계 방식을 정리했다. |
| 날짜별 실행과 재사용 | 대상 날짜를 명시하고 기존 산출물을 재사용하도록 해 중복 생성과 네트워크 병목을 줄이는 경로를 만들었다. |
| 경기 일정과 준비 상태 기반 실행 | 일정별 실행 시간, 라인업 등 입력의 준비 상태, 이미 고정한 경기 제외, 재시도와 마감 조건을 설계했다. 예약 설정·실제 실행·삭제·수동 복귀 이력을 구분했다. |
| 실행과 독립 검토 분리 | Codex가 실행을 맡고 Claude가 구조화된 결과를 검토하는 브릿지를 만들었다. 시간 제한, 입력 크기, 응답 상태를 남겨 호출 실패를 정상 분석으로 처리하지 않도록 했다. |
| 대량 추출의 전송·저장·재개 | 경기별 추출 결과를 나눠 저장하고 실패 부분만 수리했다. ChatGPT/MCP 작업 할당, 읽기 기록, 해시, 제출 검수와 재개를 시험해 전송 성공과 내용 품질을 분리했다. |

## 선수 세부정보와 시즌 갱신

특정 팀이나 대표 경기만 준비하는 데 그치지 않고, 팀·선수 인덱스와 공식 기록·PBP·Statcast를 연결해 누적 자료를 갱신했다. 상대 좌우, 구종, 존, 시즌과 최근 기간, 직접 맞대결을 구분하고 관측 수와 결측을 남겼다.

타석 도중 교체에서는 실제 투구 주인과 공식 타석 결과 귀속을 나눠 처리했다. 투구 물리 지표와 공식 타석·볼넷·삼진 집계를 분리하고, 각도 평균과 관측 분모도 점검했다. 불펜은 투수별 사용량·연투·휴식·역할로 예상 경로를 만들고 실제 등판과 비교했다.

자료가 연결됐다는 것과 LLM이 그 의미를 최종 판단에 모두 반영했다는 것은 다른 검증 과제였다. 이 차이는 연구 종료 때까지 남았다.

## 내 역할과 종료 판단

나는 문제 정의, 자료 확장, 비교 실험과 검증 범위, 적용·종료 결정을 맡았다. Claude와 Codex의 제안을 검토하고 코드 작성과 분석·검수에 AI를 활용했다. 하루 회고에만 의존하지 않고 누적 기록을 갱신하며, 맞은 사례와 모델·네레이터가 갈린 사례도 보도록 요구했다.

운영 전 리허설에서 입력·출력의 연결을 점검했고, 후기 판정 방법은 통계 기준을 충족하지 못해 운영에 적용하지 않았다. 연구·개발 기록을 남기는 것으로 프로젝트를 마감했다.
